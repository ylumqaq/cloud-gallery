# 云图库前端设计文档

> 本文档为云图库管理系统前端（`frontend/`）的详细设计说明，与后端《项目重构文档》《API 接口文档》配套阅读。
> 前端采用 React 19 + TypeScript + Vite 技术栈，通过 RESTful API 与后端 Spring Boot（端口 `8123`、上下文路径 `/api`）交互。

## 一、项目概述

- 定位：云图库管理系统的**前端单页应用（SPA）**，为「云盘 / 团队图库」提供可视化交互界面，覆盖图片上传与管理、私有空间与团队空间、细粒度成员权限控制、以图搜图、按颜色搜索、空间分析等能力。
- 技术形态：React 19 + TypeScript + Vite 单页应用，前端仓库独立于后端，通过统一 HTTP 客户端与后端交互。
- 后端依赖：基础路径 `/api`，端口 `8123`，统一响应 `BaseResponse<T>`，鉴权方式为 Sa-Token 登录态 + 空间 RBAC 权限（详见《API 接口文档》）。
- 运行方式：`pnpm dev`（开发，Vite dev server 通过代理转发到后端）、`pnpm build`（类型检查 + 生产构建）、`pnpm preview`（本地预览）。

## 三、总体架构

```

│   │   ├── request.ts       # axios 实例 + 请求/响应拦截器 + request 泛型函数
│   │   ├── user.ts          # 用户模块接口

│   ├── constants/           # 常量（权限码、角色、枚举）
│   ├── layouts/             # 布局组件（后台布局、登录布局，规划）

│   ├── utils/               # 工具函数（token 存取等）
│   └── views/               # 页面视图（按业务模块划分，.tsx）
├── vite.config.ts           # 构建配置 + 开发代理
└── package.json
```

### 3.2 设计原则

- **视图与逻辑分离**：`views` 只做页面编排，业务逻辑收敛到 `stores` / 自定义 Hooks。
- **接口层统一收敛**：所有后端请求经 `api/request.ts` 的 `request<T>` 泛型函数，统一处理 `BaseResponse`、错误码、鉴权，页面不直接操作底层请求。
- **类型先行**：后端 `BaseResponse<T>` 及各 VO 在 `types/` 中以 TS 接口定义，保证前后端契约一致，降低联调成本。
- **权限配置化**：前端权限码与角色映射沿用后端 `spaceUserAuthConfig.json` 的语义，集中定义在 `constants/`，便于维护与同步。
- **模块边界清晰**：按业务域（用户 / 图片 / 空间 / 成员 / 分析）划分目录，与后端模块一一对应，便于协作与后续演进。

## 四、核心设计

### 4.1 统一请求封装与响应处理

#### ① 统一 axios 实例

`api/request.ts` 创建唯一 axios 实例：

- `baseURL` 设为 `/api`（开发环境经 Vite 代理转发到后端 `http://localhost:8123`）。
- 统一超时时间。

```ts
const service = axios.create({
  baseURL: '/api',
  timeout: 15000,
})
```

#### ② 请求拦截器

- 从 `utils/token.ts` 的 `getToken()` 读取登录 token，注入请求头（Sa-Token 默认鉴权头 `satoken`，需与后端 `token-name` 配置一致）。

#### ③ 响应处理（`request<T>` 泛型函数）

所有接口统一返回 `BaseResponse<T>`：`{ code, data, message }`。`request<T>` 函数负责解包并统一处理错误码：

| code | 处理策略 |
| --- | --- |
| `0` | 成功，直接返回 `data` |
| `40000` | 参数错误，弹全局提示 |
| `40100` | 未登录，清除 token 并整页跳转登录页 |
| `40101` | 无权限，提示 |
| `40300` | 禁止访问，提示 |
| `40400` | 数据不存在，提示 |
| `50000` / `50001` | 服务端异常/操作失败，提示 `message` |
| 网络/HTTP 错误 | 响应拦截器兜底提示「网络异常」 |

业务侧无需再判断 `code`：

```ts
// 使用示例
const user = await getLoginUserApi()          // 返回 LoginUserVO
const page = await listPictureByPageApi()     // 返回 PageResult<PictureVO>
```

```ts
// request<T> 核心实现
export async function request<T>(config: AxiosRequestConfig): Promise<T> {
  const response = await service.request<BaseResponse<T>>(config)
  const res = response.data
  if (res.code !== 0) {
    handleBusinessError(res)
    throw res
  }
  return res.data
}
```

#### ④ Vite 开发代理

`vite.config.ts` 中配置代理，解决开发期跨域：

```ts
export default defineConfig({
  plugins: [react()],
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8123',
        changeOrigin: true,
      },
    },
  },
})
```

### 4.2 认证与登录态管理

#### ① 用户 Store（`stores/user.ts`，Zustand）

Zustand 集中管理登录态与当前用户信息：

- 状态：`token`、`loginUser`（当前登录用户脱敏信息）。
- 动作：`login`、`fetchLoginUser`（`GET /api/user/get/login`）、`logout`（`POST /api/user/logout`）、`reset`。
- 持久化：token 通过 `utils/token.ts` 写入 `localStorage`，初始化时恢复，刷新不丢登录态。

```ts
export const useUserStore = create<UserState>()((set) => ({
  token: getToken(),        // 初始化时从 localStorage 恢复
  loginUser: null,
  async login(userAccount, userPassword) {
    const res = await loginApi({ userAccount, userPassword })
    setToken(res.token)
    set({ token: res.token, loginUser: res })
  },
  // fetchLoginUser / logout / reset ...
}))
```

#### ② 登录 / 注册流程

- 登录：`POST /api/user/login` 返回用户脱敏信息 + token → 写入 store 与 localStorage → 跳转首页。
- 注册：`POST /api/user/register`（`userAccount` / `userPassword` / `checkPassword`）→ 成功后跳转登录页。
- 登出：调用 `POST /api/user/logout` 并清理本地状态 → 跳转登录页。

#### ③ 路由守卫

React Router 无内置守卫，通过 `<RequireAuth>` 包装组件实现：

1. 白名单路由（`/login`、`/register`）直接放行。
2. 未登录访问受保护路由 → `<Navigate to="/login">` 并携带来源路径。
3. 需要特定系统角色（如 `super_admin`）的路由 → 校验 `loginUser.userRole`。

```tsx
export default function RequireAuth({ children }: { children: ReactNode }) {
  const token = useUserStore((state) => state.token)
  const location = useLocation()
  if (!token) {
    return <Navigate to="/login" replace state={{ from: location.pathname }} />
  }
  return <>{children}</>
}
```

### 4.3 权限控制

前端权限分两层，与后端语义一致：

#### ① 系统角色（用户级）

三级角色：`user` / `admin` / `super_admin`。用于控制「谁能进入某些页面」（如修改用户角色仅 `super_admin` 可见/可用）。

#### ② 空间角色与权限码（RBAC）

空间角色：`viewer` / `editor` / `admin`；权限码 5 个：

| 权限码 | 含义 |
| --- | --- |
| `picture:view` | 查看图片 |
| `picture:upload` | 上传图片 |
| `picture:edit` | 编辑图片 |
| `picture:delete` | 删除图片 |
| `spaceUser:manage` | 管理空间成员 |

前端通过「当前用户在空间内的权限列表」驱动按钮/入口显隐。权限列表由 `GET /api/spaceUser/get?spaceId=xxx` 返回（角色 + 权限码列表）。

#### ③ 权限实现方式

- **路由级权限**：路由 `meta` 声明所需系统角色，守卫中校验。
- **按钮级权限**：React 无指令机制，改用 `<Permission>` 组件或 `hasPermission(code)` 函数条件渲染（规划）。
- **权限常量**：`constants/permission.ts` 集中定义权限码与角色，与后端 `spaceUserAuthConfig.json` 对齐。

```ts
// constants/permission.ts
export const PERMISSION = {
  PICTURE_VIEW: 'picture:view',
  PICTURE_UPLOAD: 'picture:upload',
  PICTURE_EDIT: 'picture:edit',
  PICTURE_DELETE: 'picture:delete',
  SPACE_USER_MANAGE: 'spaceUser:manage',
} as const
```

## 五、模块详细设计

### 模块一：用户模块

#### 1. 业务背景

用户通过账号密码登录/注册系统，登录后获得 Sa-Token 登录态（后端存 Redis）。用户信息需脱敏展示。系统管理员（`super_admin`）可修改其他用户角色。

#### 2. 核心设计

**① 接口封装（`api/user.ts`）**

| 方法 | 后端接口 | 说明 |
| --- | --- | --- |
| `registerApi` | `POST /api/user/register` | 注册 |
| `loginApi` | `POST /api/user/login` | 登录，返回用户脱敏信息 + token |
| `getLoginUserApi` | `GET /api/user/get/login` | 获取当前登录用户 |
| `logoutApi` | `POST /api/user/logout` | 退出登录 |
| `updateUserRoleApi` | `PUT /api/user/role` | 修改用户角色（`super_admin`） |

**② 类型定义（`types/user.ts`）**

```ts
export type SystemRole = 'user' | 'admin' | 'super_admin'

export interface LoginUserVO {
  id: number
  userAccount: string
  userName: string
  userAvatar: string
  userRole: SystemRole
}

// 登录结果：用户脱敏信息 + token
export interface LoginResultVO extends LoginUserVO {
  token: string
}

export interface UserRegisterRequest {
  userAccount: string
  userPassword: string
  checkPassword: string
}

export interface UserLoginRequest {
  userAccount: string
  userPassword: string
}
```

#### 3. 关键设计要点

- 登录成功后的 token 与用户信息统一写入 `userStore`，路由守卫读取该状态判断登录态。
- 修改用户角色页面对路由与按钮做 `super_admin` 双重校验，接口返回 `40101` 时兜底提示无权限。

### 模块二：图片模块

#### 1. 业务背景

图片模块是核心功能，覆盖上传（本地文件 / 网络 URL）、分页浏览、详情、编辑、删除、批量抓取、以图搜图、按颜色搜索。图片按空间隔离，操作需空间权限。

#### 2. 核心设计

**① 接口封装（`api/picture.ts`）**

| 方法 | 后端接口 | 说明 |
| --- | --- | --- |
| `uploadPictureApi` | `POST /api/picture/upload` | 上传（`file` 或 `fileUrl` 二选一，FormData） |
| `listPictureByPageApi` | `GET /api/picture/list/page/vo` | 分页查询 |
| `getPictureApi` | `GET /api/picture/get/{id}` | 图片详情 |
| `editPictureApi` | `POST /api/picture/edit` | 编辑图片 |
| `deletePictureApi` | `POST /api/picture/delete` | 删除图片（双删 COS + 向量） |
| `uploadPictureByBatchApi` | `POST /api/picture/upload/batch` | 批量抓取上传 |
| `searchByPictureApi` | `POST /api/picture/search/by/picture` | 以图搜图 |
| `searchByColorApi` | `GET /api/picture/search/color` | 按颜色搜索 |

**② 上传设计**

- 本地上传：Ant Design `Upload` 组件，选中文件后通过 `FormData` 提交；前端做文件类型（jpeg/png/jpg/webp）与大小（≤ 2MB）预校验。
- URL 上传：表单输入图片 URL，直接以 `fileUrl` 参数提交。
- 公共参数：`spaceId`（空 = 公共图库）、`picName`、`category`、`tags`（JSON 数组字符串）。

**③ 图片列表与展示**

- 瀑布流/栅格布局展示图片卡片，卡片含缩略图、名称、分类、标签、大小、主色调。
- 分页参数：`current`、`pageSize`、`spaceId`、`searchText`、`picColor`。

**④ 以图搜图与按颜色搜索**

- 以图搜图：上传查询图（`file` / `fileUrl`）+ `spaceId` + `topK`（默认 20），展示相似图片列表。
- 按颜色搜索：颜色选择器转十六进制 `picColor`（如 `0xff0000`）+ `spaceId` + `topN`，展示按欧氏距离升序的相近图片。

**⑤ 类型定义（`types/picture.ts`）**

```ts
export interface PictureVO {
  id: number
  url: string
  thumbnailUrl?: string
  name: string
  category?: string
  tags?: string[]        // 后端存储为 JSON 数组字符串，前端解析
  picSize?: number
  picWidth?: number
  picHeight?: number
  picColor?: string
  spaceId?: number       // 空 = 公共图库
  createTime?: string
  editTime?: string
}

export interface PictureQueryRequest {
  current: number
  pageSize: number
  spaceId?: number
  searchText?: string
  picColor?: string
}

export interface PictureEditRequest {
  id: number
  name?: string
  category?: string
  tags?: string          // JSON 数组字符串
  spaceId?: number
}
```

#### 3. 关键设计要点

- `tags` 字段后端约定为 JSON 数组字符串，前端统一 `JSON.stringify` / `JSON.parse` 转换。
- 删除图片为破坏性操作，前端二次确认。
- 分页查询 `spaceId` 为空与不传语义需区分（公共图库 vs 不限定），统一用 `undefined` 表示「不限定」。

### 模块三：空间模块

#### 1. 业务背景

空间分私有（`spaceType=0`）与团队（`spaceType=1`）两类。用户可创建空间，创建者或管理员可编辑、删除空间；所有登录用户可查看空间详情与自己的空间列表。

#### 2. 核心设计

**① 接口封装（`api/space.ts`）**

| 方法 | 后端接口 | 说明 |
| --- | --- | --- |
| `addSpaceApi` | `POST /api/space/add` | 创建空间（`spaceName` / `spaceType`） |
| `editSpaceApi` | `POST /api/space/edit` | 编辑空间名称 |
| `deleteSpaceApi` | `POST /api/space/delete` | 删除空间 |
| `getSpaceApi` | `GET /api/space/get/{id}` | 空间详情 |
| `listMySpaceApi` | `GET /api/space/list` | 我的空间列表 |

**② 类型定义（`types/space.ts`）**

```ts
export type SpaceType = 0 | 1

export interface SpaceVO {
  id: number
  spaceName: string
  spaceType: SpaceType
  userId?: number
  createTime?: string
  editTime?: string
}

export interface SpaceAddRequest {
  spaceName: string
  spaceType: SpaceType
}

export interface SpaceEditRequest {
  id: number

```

#### 3. 关键设计要点

- 空间列表页展示私有/团队类型标识，团队空间入口提供成员管理、分析等子功能。
- 删除空间需二次确认；后端校验创建者或管理员权限，前端按角色隐藏无权按钮。
- 当前选中空间存入 `spaceStore`，供图片列表、成员管理、分析页面共享。

### 模块四：空间成员模块

#### 1. 业务背景

团队空间支持成员管理，空间内角色 `viewer` / `editor` / `admin`。管理员（`spaceUser:manage`）可添加、修改角色、移除成员；`picture:view` 可查看成员列表；当前用户可查询自己在某空间的权限。

#### 2. 核心设计

**① 接口封装（`api/spaceUser.ts`）**

| `deleteSpaceUserApi` | `POST /api/spaceUser/delete` | 移除成员 |
| `listSpaceUserApi` | `GET /api/spaceUser/list` | 成员列表 |
| `getMySpacePermissionApi` | `GET /api/spaceUser/get` | 当前用户在某空间权限 |

**② 类型定义（`types/spaceUser.ts`）**

```ts
export type SpaceRole = 'viewer' | 'editor' | 'admin'

export interface SpaceUserVO {
  id: number
  spaceId: number
  userId: number
  spaceRole: SpaceRole
  userAccount?: string
  userName?: string
  userAvatar?: string
}

  spaceRole?: SpaceRole

```

#### 3. 关键设计要点

- 进入空间页面时调用 `GET /api/spaceUser/get?spaceId=xxx` 获取权限列表，存入 `spaceStore`，驱动页面内按钮显隐。
- 角色展示做 `viewer` / `editor` / `admin` 中文映射。
- 移除成员需二次确认，且不可移除空间创建者（后端兜底校验）。

### 模块五：空间分析模块

#### 1. 业务背景

对空间（或公共图库）做使用、分类、标签、大小四类分析，系统管理员可查看空间用量排行 TopN。分析结果适合用图表可视化。

#### 2. 核心设计

**① 接口封装（`api/spaceAnalyze.ts`）**

| 方法 | 后端接口 | 说明 |

#### 3. 关键设计要点

- 使用分析用进度条/仪表盘展示使用率（`countUsageRatio` / `sizeUsageRatio`）。
- 分类/标签分析用柱状图或饼图（ECharts）展示 `count` 与 `totalSize`。
- 大小分析用区间分布图，区间固定为 `<100KB` / `100KB-500KB` / `500KB-1MB` / `>1MB` / `未知`。
- 排行接口仅系统管理员可访问，页面/入口需 `admin` 及以上角色校验。
- 所有分析接口 `spaceId` 为空表示统计公共图库。

## 六、关键设计要点汇总

1. **统一响应收敛**：所有接口经 `api/request.ts` 的 `request<T>` 解包 `BaseResponse`，业务侧直接拿 `data`。
2. **双层权限**：系统角色（页面/路由级）+ 空间权限码（按钮级），权限码集中常量管理。
3. **登录态持久化**：token 由 `utils/token.ts` 存取 localStorage，Zustand 初始化时恢复，刷新不丢登录态。
4. **类型契约**：`types/` 与后端 VO 一一对应，`tags` 等 JSON 字符串字段统一转换。
5. **上传预校验**：本地文件类型/大小在前端预校验，减少无效请求。
6. **破坏性操作二次确认**：删除图片、删除空间、移除成员等操作统一二次确认。
7. **空值语义区分**：`spaceId` 为空（公共图库）与不传（不限定）语义需在查询层明确区分。
8. **图表可视化**：分析模块用 ECharts 呈现。
