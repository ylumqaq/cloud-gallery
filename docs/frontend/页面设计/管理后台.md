# 管理后台页面设计（空间用量排行 / 用户角色管理）

> 所属路由：`/admin/rank`（空间用量排行）、`/admin/user`（用户角色管理）。配套《前端设计文档》《组件设计文档》《状态管理设计文档》《API 接口文档》。

## 一、页面定位

系统管理员专属页面：查看空间用量排行 TopN，以及修改用户系统角色（仅 `super_admin`）。

## 二、路由与权限

| 页面 | 路由 | 权限 |
| --- | --- | --- |
| 空间用量排行 | `/admin/rank` | 登录 + 系统管理员（`admin` / `super_admin`） |
| 用户角色管理 | `/admin/user` | 登录 + `super_admin` |

- 路由级权限：除 `RequireAuth` 外，还需校验 `loginUser.userRole`（见《前端设计文档》4.3）。
- 无权限访问时重定向首页或提示无权限。

## 三、布局与组件树

```
MainLayout
├── SpaceRankPage（/admin/rank）
│   ├── topN 选择（默认 10）
│   └── SpaceRankTable（排行表格）
└── UserRolePage（/admin/user）
    ├── 用户角色表单（targetUserId + userRole 选择）
    └── 提交按钮
```

## 四、页面内状态（useState）

### 空间用量排行

| 状态 | 类型 | 说明 |
| --- | --- | --- |
| rankList | `SpaceRankAnalyzeVO[]` | 排行数据 |
| topN | `number` | 返回数量，默认 10 |
| loading | `boolean` | 加载中 |

### 用户角色管理

| 状态 | 类型 | 说明 |
| --- | --- | --- |
| form | `{ targetUserId: number; userRole: string }` | 表单 |
| submitting | `boolean` | 提交中 |

## 五、接口调用

| 时机 | 接口 | 参数 |
| --- | --- | --- |
| 进入排行页 / 调整 topN | `getSpaceRankApi(topN)` | 数量 |
| 提交角色修改 | `updateUserRoleApi` | `targetUserId`、`userRole` |

## 六、交互流程

### 空间用量排行

1. 进入页面：校验系统管理员角色 → 调 `getSpaceRankApi` 拉取排行。
2. 调整 `topN` → 重新拉取。
3. 表格展示：空间 ID、图片数量、总大小（格式化）。

### 用户角色管理

1. 进入页面：校验 `super_admin` 角色。
2. 输入 `targetUserId` + 选择 `userRole`（`user` / `admin` / `super_admin`）。
3. 提交 → `updateUserRoleApi` → 成功提示。

## 七、权限显隐

- 排行页：`admin` / `super_admin` 可见；普通 `user` 不显示入口且访问被拦截。
- 角色管理页：仅 `super_admin` 可见。

## 八、加载 / 空 / 错误态

- 加载中：表格 `loading` / `Spin`。
- 空排行：`Empty`。
- 提交失败：拦截器统一提示；无权限后端返回 `40101`。

## 九、关键注意点

1. 系统角色校验在路由层 + 接口层双重保障（前端拦截 + 后端 `@SaCheckRole`）。
2. **用户角色管理的 `targetUserId` 缺口**：后端无「按账号查用户」接口，需手动输入用户 ID（数字），与空间成员添加同类问题，后续随后端用户查询接口一并优化。
3. 修改角色为敏感操作，建议二次确认；后端兜底「不能修改自己」「不能移除最后一个 super_admin」。
