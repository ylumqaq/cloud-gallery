# 登录 / 注册页面设计

> 所属路由：`/login`、`/register`。配套《前端设计文档》《状态管理设计文档》《API 接口文档》。

## 一、页面定位

登录页与注册页为公开页面，使用独立居中布局（不套 `MainLayout`），完成账号密码登录与账号注册。

## 二、路由与权限

| 页面 | 路由 | 权限 | 说明 |
| --- | --- | --- | --- |
| 登录 | `/login` | 公开 | 已登录访问时可直接跳转首页 |
| 注册 | `/register` | 公开 | 注册成功后跳转登录页 |

## 三、布局与组件树

```
登录页 / 注册页（独立居中布局，无 MainLayout）
└── Card（居中，宽 360）
    └── Form（账号 + 密码 [+ 确认密码]）
```

- 背景统一浅灰，内容垂直水平居中，参考已落地的 `LoginPage`。

## 四、页面内状态（useState）

| 状态 | 类型 | 说明 |
| --- | --- | --- |
| loading | `boolean` | 提交中 |

- 登录态由 `useUserStore` 维护，页面只读 `login` 动作。

## 五、接口调用

| 时机 | 接口 | 参数 |
| --- | --- | --- |
| 登录提交 | `loginApi` → `useUserStore.login` | `userAccount`、`userPassword` |
| 注册提交 | `registerApi` | `userAccount`、`userPassword`、`checkPassword` |

## 六、交互流程

### 登录

1. 输入账号、密码 → 点击「登录」。
2. 调 `useUserStore.login(account, password)`：内部 `loginApi` 返回 `LoginUserVO`（含 token），store 分离 token 与脱敏信息后持久化。
3. 成功：`message.success` → 跳转首页 `/`（或来源路径 `location.state.from`）。
4. 失败：错误提示由拦截器统一处理，页面 catch 后不重复提示。

### 注册

1. 输入账号、密码、确认密码。
2. 前端校验：两次密码一致、必填。
3. 调 `registerApi` → 成功 `message.success` → 跳转 `/login`。

## 七、权限显隐

- 两页均公开，无按钮级权限。
- 已登录用户访问登录 / 注册页，可重定向到首页（避免重复登录）。

## 八、加载 / 空 / 错误态

- 提交中：按钮 `loading`。
- 两次密码不一致：前端表单校验提示，不发起请求。
- 登录 / 注册失败：拦截器统一提示（如「账号或密码错误」等后端 message）。

## 九、关键注意点

1. 登录成功后 token 由 `useUserStore.login` 写入 localStorage（`utils/token.ts`），刷新不丢登录态。
2. 登录页需处理「来源路径」：未登录访问受保护路由被 `RequireAuth` 重定向到 `/login` 并携带 `state.from`，登录成功后优先跳回原路径。
3. 注册接口返回 `userId`（后端 `Long`），前端不消费即可。
