# 图片详情页面设计

> 所属路由：`/picture/:id`。配套《前端设计文档》《组件设计文档》《状态管理设计文档》《API 接口文档》。

## 一、页面定位

展示单张图片的原图 / 缩略图与完整元信息，提供编辑（名称 / 分类 / 标签 / 目标空间）与删除操作入口。

## 二、路由与权限

| 项 | 说明 |
| --- | --- |
| 路由 | `/picture/:id`（`id` 为图片 ID） |
| 权限 | 登录 + 图片所在空间 `picture:view`（公共图库登录即可） |
| 前置 | 由 `RequireAuth` 包裹 |

## 三、布局与组件树

```
MainLayout
└── PictureDetailPage
    ├── Row / Col
    │   ├── 图片展示区（Image，支持预览放大）
    │   └── 元信息区（Descriptions）
    ├── 操作区（编辑按钮 / 删除按钮 / 返回按钮）
    └── EditPictureModal（编辑弹窗）
```

## 四、页面内状态（useState）

| 状态 | 类型 | 说明 |
| --- | --- | --- |
| picture | `PictureVO \| null` | 图片详情 |
| loading | `boolean` | 详情加载中 |
| editModalOpen | `boolean` | 编辑弹窗是否打开 |

## 五、接口调用

| 时机 | 接口 | 参数 |
| --- | --- | --- |
| 进入页面 | `getPictureApi(id)` | 路由参数 `:id` |
| 保存编辑 | `editPictureApi` | `id`、`name`、`category`、`tags`、`spaceId` |
| 删除 | `deletePictureApi(id)` | 图片 ID |

## 六、交互流程

1. 进入页面：从路由读取 `:id` → 调 `getPictureApi` → 填充 `picture`。
2. 展示：原图优先 `picture.url`，缩略图 `picture.thumbnailUrl`；点击原图用 Ant Design `Image` 预览放大。
3. 元信息展示字段：名称、分类、标签（`Tag` 组）、大小（字节格式化）、尺寸（宽 × 高）、格式、主色调（色块）、上传者、创建时间、最近编辑时间。
4. 编辑：点击「编辑」→ 打开 `EditPictureModal`，字段为名称 / 分类 / 标签 / 目标空间；提交调 `editPictureApi`，成功后刷新详情并关闭弹窗。
5. 删除：二次确认 → `deletePictureApi` → 成功后 `message` 提示并返回列表页（`navigate(-1)` 或跳 `/`）。

## 七、权限显隐

| 操作 | 权限码 | 说明 |
| --- | --- | --- |
| 查看详情 | `picture:view` | 公共图库默认有；空间按 `spacePermission` |
| 编辑 | `picture:edit` | 仅空间 `editor` / `admin` |
| 删除 | `picture:delete` | 仅空间 `admin` |

- 通过 `Permission` 组件控制编辑 / 删除按钮显隐。

## 八、加载 / 空 / 错误态

- 加载中：`Spin` 居中。
- 图片不存在或无权查看：后端返回 `40400` / `40101`，拦截器提示；页面可展示「图片不存在」空态并引导返回。
- 编辑 / 删除失败：拦截器统一提示。

## 九、关键注意点

1. `tags` 编辑时：输入用 `Select mode="tags"` 得到 `string[]`，提交前 `JSON.stringify` 转 JSON 数组字符串（与后端约定一致）。
2. 编辑空间（`spaceId`）涉及跨空间移动，需二次确认，且需目标空间 `picture:upload` 权限（后端兜底校验）。
3. 删除为破坏性操作，二次确认。
