# 前端实施计划文档

> 本文档为云图库前端（`frontend/`）的落地实施计划，配套《前端设计文档》《组件设计文档》《状态管理设计文档》《页面设计》《接口对接清单》阅读。
> 实施顺序遵循「依赖优先」：先公共基础设施，再按页面链路分批落地，最后联调收尾。

## 一、目标与范围

将前端从「脚手架 + 少量落地代码」推进到完整可用的 SPA，覆盖：

- 登录 / 注册
- 图片列表 / 详情 / 上传 / 以图搜图
- 我的空间 / 空间图片 / 空间成员 / 空间分析
- 管理后台（空间用量排行 / 用户角色管理）

## 二、前置条件与阻塞项

### 2.1 需后端配合（阻塞交互体验，但不阻塞前端先行）

| 事项 | 影响 | 前端应对 |
| --- | --- | --- |
| 4 处权限注解疑似遗漏（见《接口对接清单》四） | 空间详情 / 以图搜图 / 颜色搜索 / 排行可能越权 | 后端确认后修正；前端按文档权限设计 |
| 无「按账号查用户」接口 | 成员添加、角色管理只能手动输入 userId | 暂用手动输入 userId，后续替换为搜索 |

### 2.2 前端需自行完成

- 安装 ECharts：`pnpm add echarts`（空间分析图表依赖）。

## 五、验收标准（整体）

1. `pnpm build` 无类型错误、构建成功。
2. 登录 / 注册 / 图片 / 空间 / 成员 / 分析 / 管理后台全流程可操作。
3. 按钮级权限与路由级权限与《前端设计文档》《组件设计文档》一致。
4. 所有页面接口调用与《接口对接清单》一致，无遗漏。

## 六、风险与注意事项

1. **权限注解风险**：后端 4 处疑似漏注解未确认前，前端按文档权限实现，但实际越权需后端兜底。
2. **ECharts 首版从简**：分析图表先跑通柱状图 / 进度条，饼图、仪表盘等按需迭代。
3. **userId 手动输入**：成员添加 / 角色管理为临时方案，后端补充用户查询接口后替换。
4. **空间上下文清理**：离开空间页面需清理 `spaceStore.currentSpace`，避免权限误判（见《空间图片》文档）。
5. **破坏性操作统一二次确认**：删除图片 / 空间、移除成员、修改角色等。
