# 阶段 5：以图搜图（已完成）

> 本阶段状态：已完成。以下为结合实际代码的落地内容，按「写代码时的实现步骤」组织。

## 一、阶段目标

使用腾讯云数据万象 CI 托管图片检索实现「以图搜图」，打通「上传图片 → CI 入库 → 以图搜图 → 删除图片出库」完整链路，全程不依赖本地向量提取与 PostgreSQL。

## 二、方案概述与关键决策

### 1. 为什么使用 CI 托管图片检索

以图搜图的「向量提取 + 相似度检索」由腾讯云数据万象 CI 的「图像搜索」能力托管完成，应用侧只需负责「入库 / 出库 / 检索」三个动作的封装，无需维护本地向量库，也无需在本地提取图片特征向量。

### 2. 腾讯云 CI 的能力边界（重要背景）

查阅腾讯云 COS SDK（`5.6.227`）后确认：数据万象 CI **只提供托管式图片检索**（`addGalleryImages` 入库 → `searchGalleryImages`/`searchImage` 检索，返回匹配图片列表 + 分数），**并不提供「输入图片 → 返回 embedding 向量」的接口**。因此本项目不引入本地向量提取与 PostgreSQL 向量库，直接复用 CI 托管图片检索能力。

「图像搜索」属于数据万象「内容识别」分类，随内容识别一并开通；首次使用前需先调用 `openImageSearch` 建立图库（图库容量设置后不可修改）。

### 3. 检索链路说明

| 环节 | 实现方式 |
| --- | --- |
| 入库 | 上传成功后调用 `addGalleryImage(原图对象键, 图片ID)`，`entityId` 保存图片 ID |
| 出库 | 删除后从 URL 解析对象键，调用 `deleteGalleryImage(对象键, 图片ID)` |
| 检索 | 查询图临时上传 COS（`search/query/xxx`）→ `searchGalleryImages(临时键, topK)` 返回图片 ID 列表 → MySQL 回查详情 |
| 空间过滤 | CI 只返回相似图片 ID，空间与删除状态过滤由 MySQL 兜底 |

## 三、实际完成内容（按实现步骤）

### 步骤 1：扩展 CosManager

修改 `manager/CosManager.java`，新增「开通图库」与「CI 图库检索」封装：

```java
// 开通 Bucket 以图搜图图库（一次性操作，图库容量设置后不可修改）
public void openImageSearch(String maxCapacity, String maxQps) {
    OpenImageSearchRequest request = new OpenImageSearchRequest();
    request.setBucketName(cosClientConfig.getBucket());
    request.setMaxCapacity(maxCapacity);
    request.setMaxQps(maxQps);
    cosClient.openImageSearch(request);
}

// 加入 CI 以图搜图图库，entityId 保存 pictureId
public void addGalleryImage(String key, long pictureId) {
    ImageSearchRequest request = new ImageSearchRequest();
    request.setBucketName(cosClientConfig.getBucket());
    request.setObjectKey(key);
    request.setEntityId(String.valueOf(pictureId));
    cosClient.addGalleryImages(request);
}

// 从 CI 图库移除图片（DeleteImage 请求体需携带 entityId）
public void deleteGalleryImage(String key, long pictureId) {
    ImageSearchRequest request = new ImageSearchRequest();
    request.setBucketName(cosClientConfig.getBucket());
    request.setObjectKey(key);
    request.setEntityId(String.valueOf(pictureId));
    cosClient.deleteGalleryImages(request);
}

// CI 以图搜图，返回相似 pictureId 列表
public List<Long> searchGalleryImages(String queryKey, int limit) {
    ImageSearchRequest request = new ImageSearchRequest();
    request.setBucketName(cosClientConfig.getBucket());
    request.setObjectKey(queryKey);
    request.setLimit(String.valueOf(limit));
    ImageSearchResponse response = cosClient.searchGalleryImages(request);
    List<Long> pictureIds = new ArrayList<>();
    if (response == null || response.getImageInfos() == null) return pictureIds;
    for (ImageInfos info : response.getImageInfos()) {
        if (StrUtil.isNotBlank(info.getEntityId())) {
            pictureIds.add(Long.valueOf(info.getEntityId()));
        }
    }
    return pictureIds;
}
```

设计要点：

- COS SDK 的 `addGalleryImages` 走 `ci-process=ImageSearch&action=AddImage`，XML 请求体只序列化 `EntityId` / `CustomContent` / `Tags` 三个字段；`searchGalleryImages` 返回的 `ImageInfos.entityId` 即入库时的 `pictureId`，实现「CI 检索结果 → pictureId」的映射。

### 步骤 2：实现 CiImageSearchStrategy

新建 `service/search/CiImageSearchStrategy.java`，普通 `@Component`，直接注入 `CosManager`：

```java
@Slf4j
@Component
public class CiImageSearchStrategy {

    @Resource private CosManager cosManager;

    // 上传成功后：把图片对象加入 CI 图库，entityId 保存 pictureId
    public void onUpload(Picture picture, UploadPictureResult result) {
        try {
            cosManager.addGalleryImage(result.getOriginalKey(), picture.getId());
        } catch (Exception e) {
            log.warn("CI 图库入库失败（最终一致，不影响图片上传），pictureId={}", picture.getId(), e);
        }
    }

    // 删除后：从 URL 解析对象键，CI 图库出库
    public void onDelete(Picture picture) {
        try {
            String key = extractKey(picture.getUrl());
            if (key != null) {
                cosManager.deleteGalleryImage(key, picture.getId());
            }
        } catch (Exception e) {
            log.warn("CI 图库出库失败（最终一致），pictureId={}", picture.getId(), e);
        }
    }

    // 以图搜图：查询图临时上传 COS，检索后清理临时对象
    public List<Long> search(File queryFile, Long spaceId, int topK) {
        String suffix = FileUtil.getSuffix(queryFile.getName());
        if (StrUtil.isBlank(suffix)) suffix = "jpg";
        String queryKey = "search/query/" + RandomUtil.randomString(16) + "." + suffix;
        cosManager.putObject(queryKey, queryFile); // CI 检索要求查询图位于 COS
        try {
            return cosManager.searchGalleryImages(queryKey, topK);
        } finally {
            try { cosManager.deleteObject(queryKey); } catch (Exception e) { log.warn(...); }
        }
    }
}
```

设计要点：

- `CiImageSearchStrategy` 为普通 `@Component`，不再实现任何策略接口、不带 `@ConditionalOnProperty`、无 `name()`，是全项目唯一的以图搜图实现。
- `onUpload` / `onDelete` 内部 try-catch 兜底，失败仅记日志，符合《事务设计文档》「副本缺失可容忍、可修复」的最终一致原则，不影响图片上传 / 删除主流程。
- `search` 返回 `List<Long>`（pictureId）；入库时用 `entityId` 保存 `pictureId`，检索时由 CI 原样带回再解析。

以图搜图实现：

```java
@Override
public List<PictureVO> searchPictureByPicture(PictureSearchByPictureRequest request) {
    long userId = StpUtil.getLoginIdAsLong();
    Long spaceId = request.getSpaceId();
    int topK = request.getTopK() != null && request.getTopK() > 0
            ? request.getTopK() : PictureConstant.DEFAULT_SEARCH_TOP_K;

    // 空间图片需校验查看权限；公共图库所有登录用户可搜
    if (spaceId != null) {
        checkSpacePermission(spaceId, userId, SpaceUserConstant.PERMISSION_PICTURE_VIEW);
    }

    File queryFile = null;
    try {
        queryFile = resolveQueryFile(request); // 本地文件转存 或 URL 下载为临时文件
        List<Long> pictureIds = ciImageSearchStrategy.search(queryFile, spaceId, topK);
        if (pictureIds.isEmpty()) return List.of();
        // 回查 MySQL 详情，保留相似度顺序，并兜底过滤空间与已删除图片
        return listPictureVOByIds(pictureIds, spaceId);
    } finally {
        deleteTempFile(queryFile);
    }
}
```

辅助方法：

- `resolveQueryFile`：将 `MultipartFile` 转存或 `fileUrl` 下载为本地临时文件（保留原后缀）。
- `listPictureVOByIds`：按 `pictureIds` 回查 MySQL（`in` 查询 + `spaceId` 过滤），用 `Map` 按相似度顺序组装，并自动过滤已逻辑删除的图片。

事务顺序（遵循《事务设计文档》）：

- **上传**：COS 上传 → MySQL 写 `picture`（本地事务）→ CI 图库入库（事务外，最终一致）。
- **删除**：MySQL 逻辑删 → CI 图库出库 → COS 删对象（最终一致）。
- **以图搜图**：只读（CI 检索 + MySQL 回查，以 MySQL 为准过滤）。
