# 阶段 5：以图搜图（已完成）

> 本阶段状态：已完成。以下为结合实际代码的落地内容，按「写代码时的实现步骤」组织。

## 一、阶段目标

实现图片向量提取、存储与相似度检索（MySQL + PostgreSQL 双库），打通「上传图片 → 写入向量 → 以图搜图 → 删除图片双删」完整链路，并采用**策略模式**支持两种可切换的以图搜图实现：

1. **`pg` 策略（默认）**：本地提取图片特征向量 → 写入自建 PostgreSQL `picture_embedding` 表 → 应用侧用 pgvector 余弦距离检索；
2. **`ci` 策略**：不提取中间向量，直接复用腾讯云数据万象 CI 的「图像搜索」托管图片检索能力（`addGalleryImages` / `searchGalleryImages`）。「图像搜索」属于「内容识别」分类，随内容识别一并开通；首次使用前需先调用 `openImageSearch` 建立图库。

## 二、方案概述与关键决策

### 1. 为什么用策略模式

以图搜图的「向量来源」存在两种差异较大的实现路径，且用户希望后续能方便切换，因此把「提取 + 检索」抽象为统一接口 `ImageSearchStrategy`，两个实现通过配置项 `image-search.strategy` 一键切换，业务层（`PictureServiceImpl`）只依赖接口、不感知具体实现。

### 2. 腾讯云 CI 的能力边界（重要背景）

查阅腾讯云 COS SDK（`5.6.227`）后确认：数据万象 CI **只提供托管式图片检索**（`addGalleryImages` 入库 → `searchGalleryImages`/`searchImage` 检索，返回匹配图片列表 + 分数），**并不提供「输入图片 → 返回 512 维 embedding 向量」的接口**。

因此「CI 提取向量 → 写自建 pgvector」的原始文档架构在真实 CI 上无法直接落地，本阶段用「本地视觉特征（降级）+ CI 托管检索」两种策略分别覆盖两种诉求：前者打通 pgvector 双库链路、可本地完整跑通；后者复用腾讯云「图像搜索」能力（属于「内容识别」），已通过真实 CI 端到端验证。

### 3. 两种策略对比

| 维度 | `pg` 策略（默认） | `ci` 策略 |
| --- | --- | --- |
| 向量提取 | 本地 `LocalImageEmbeddingExtractor`（纯 JDK，无需模型） | 不提取，CI 入库时托管提取 |
| 向量存储 | 自建 PostgreSQL `picture_embedding`（pgvector） | CI 图片搜索图库（云端） |
| 检索 | 应用侧 pgvector 余弦距离 `<=>` | CI `searchGalleryImages` |
| 语义能力 | 颜色 / 构图相似（非语义级） | 腾讯云托管语义检索 |
| 外部依赖 | PostgreSQL + pgvector | 数据万象「图像搜索」能力（属内容识别，需先 openImageSearch 建图库） |

### 步骤 1：接入 PostgreSQL 独立数据源

新建 `config/DataSourceConfig.java`：显式声明 **MySQL 主数据源（`@Primary`）+ PostgreSQL 向量库数据源**，并为 PG 提供独立 `JdbcTemplate`。

```java
@Configuration
public class DataSourceConfig {

    @Bean("mysqlDataSourceProperties")
    @ConfigurationProperties(prefix = "spring.datasource")
    public DataSourceProperties mysqlDataSourceProperties() {
        return new DataSourceProperties();
    }

    @Bean("mysqlDataSource")
    @Primary
    public DataSource mysqlDataSource(@Qualifier("mysqlDataSourceProperties") DataSourceProperties properties) {
        return properties.initializeDataSourceBuilder().build();
    }

    @Bean("pgDataSourceProperties")
    @ConfigurationProperties(prefix = "pg.datasource")
    public DataSourceProperties pgDataSourceProperties() {
        return new DataSourceProperties();
    }

    @Bean("pgDataSource")
    public DataSource pgDataSource(@Qualifier("pgDataSourceProperties") DataSourceProperties properties) {
        return properties.initializeDataSourceBuilder().build();
    }

    @Bean("pgJdbcTemplate")
    public JdbcTemplate pgJdbcTemplate(@Qualifier("pgDataSource") DataSource dataSource) {
        return new JdbcTemplate(dataSource);
    }
}
```

设计要点：

- 用 `DataSourceProperties` + `initializeDataSourceBuilder()` 创建数据源，解决 Hikari 的 `url`（业务配置字段）与 `jdbcUrl`（Hikari 字段）不一致导致的属性绑定问题。
- PG 数据源绑定自定义前缀 `pg.datasource`（`application.yml` 中已有占位配置），与主数据源 `spring.datasource` 完全隔离。
- PG 采用 `JdbcTemplate`（而非 MyBatis 多数据源）直接操作，理由：pgvector 的 `vector` 类型 + 余弦距离运算符用原生 SQL 最直接可控，避免引入 MyBatis 多数据源与类型处理器复杂度。

> 说明：本步骤最初命名为 `PgDataSourceConfig`、仅声明 PG 数据源；测试后发现「主数据源被抢占」的全局回归问题，重构为现在的 `DataSourceConfig`（详见「四、问题修复记录」）。

### 步骤 2：实现 PictureEmbeddingMapper（pgvector 向量表访问）

新建 `mapper/PictureEmbeddingMapper.java`，用 `@Repository` + `pgJdbcTemplate` 提供向量的写入 / 删除 / 余弦检索：

```java
@Repository
public class PictureEmbeddingMapper {

    private final JdbcTemplate jdbcTemplate;

    public PictureEmbeddingMapper(@Qualifier("pgJdbcTemplate") JdbcTemplate jdbcTemplate) {
        this.jdbcTemplate = jdbcTemplate;
    }

    // 幂等写入：主键冲突时覆盖
    public void upsert(long pictureId, Long spaceId, List<Float> embedding) {
        String sql = "INSERT INTO picture_embedding (picture_id, space_id, embedding) "
                + "VALUES (?, ?, CAST(? AS vector)) "
                + "ON CONFLICT (picture_id) DO UPDATE SET space_id = EXCLUDED.space_id, embedding = EXCLUDED.embedding";
        jdbcTemplate.update(sql, pictureId, spaceId, toVectorString(embedding));
    }

    // 删除向量（双删）
    public void deleteByPictureId(long pictureId) {
        jdbcTemplate.update("DELETE FROM picture_embedding WHERE picture_id = ?", pictureId);
    }

    // 余弦距离检索，按相似度升序（<=> 越小越相似）
    public List<Long> searchSimilarPictureIds(List<Float> embedding, Long spaceId, int topK) {
        String vector = toVectorString(embedding);
        if (spaceId == null) {
            String sql = "SELECT picture_id FROM picture_embedding "
                    + "WHERE space_id IS NULL ORDER BY embedding <=> CAST(? AS vector) LIMIT ?";
            return jdbcTemplate.queryForList(sql, Long.class, vector, topK);
        }
        String sql = "SELECT picture_id FROM picture_embedding "
                + "WHERE space_id = ? ORDER BY embedding <=> CAST(? AS vector) LIMIT ?";
        return jdbcTemplate.queryForList(sql, Long.class, spaceId, vector, topK);
    }

    private String toVectorString(List<Float> embedding) {
        StringBuilder sb = new StringBuilder("[");
        for (int i = 0; i < embedding.size(); i++) {
            if (i > 0) sb.append(',');
            sb.append(embedding.get(i));
        }
        return sb.append(']').toString();
    }
}
```

设计要点：

- 向量在 JDBC 层以 pgvector 字符串字面量 `[x1,x2,...]` 传递，配合 `CAST(? AS vector)` 完成类型转换。
- 检索使用 pgvector 余弦距离运算符 `<=>`（与数据库设计文档的 `vector_cosine_ops` 索引一致），值越小越相似。
- `spaceId` 过滤：`spaceId == null` 表示仅检索公共图库（`space_id IS NULL`），否则限定指定空间。

### 步骤 3：实现本地视觉特征向量提取器

新建 `service/search/LocalImageEmbeddingExtractor.java`，纯 JDK（`ImageIO` + `BufferedImage`）实现，无需任何模型：

```java
@Component
public class LocalImageEmbeddingExtractor {

    private static final int DIMENSION = 512; // 与 picture_embedding.embedding vector(512) 一致
    private static final int SIZE = 16;        // 16×16 = 256 像素，每像素取 R、G 两通道共 512 维

    public List<Float> extract(File file) {
        BufferedImage scaled = scale(readImage(file));
        List<Float> vector = new ArrayList<>(DIMENSION);
        for (int y = 0; y < SIZE; y++) {
            for (int x = 0; x < SIZE; x++) {
                int rgb = scaled.getRGB(x, y);
                int red = (rgb >> 16) & 0xFF;
                int green = (rgb >> 8) & 0xFF;
                vector.add(red / 255.0f);
                vector.add(green / 255.0f);
            }
        }
        return vector;
    }
    // readImage / scale（双线性插值缩放到 16×16）省略
}
```

算法说明：

- 将图片缩放到固定 `16×16`，取每个像素的 R、G 两通道并归一化到 `[0,1]`，得到固定 512 维向量。
- 视觉上颜色、构图相近的图片会得到相近向量；相同图片向量完全一致（确定性）。
- 该实现是语义级模型（如 CLIP）缺失时的降级方案，后续替换 `LocalImageEmbeddingExtractor` 即可无缝升级，策略结构无需改动。

**4.1 `pg` 策略** — `PgVectorImageSearchStrategy.java`

```java
@Slf4j
@Component
@ConditionalOnProperty(prefix = "image-search", name = "strategy", havingValue = "pg", matchIfMissing = true)
public class PgVectorImageSearchStrategy implements ImageSearchStrategy {

    @Resource private CosManager cosManager;
    @Resource private LocalImageEmbeddingExtractor embeddingExtractor;
    @Resource private PictureEmbeddingMapper pictureEmbeddingMapper;

    @Override
    public void onUpload(Picture picture, UploadPictureResult result) {
        File tempFile = null;
        try {
            tempFile = File.createTempFile("embedding_" + picture.getId(), ".tmp");
            cosManager.downloadObject(result.getOriginalKey(), tempFile); // 从 COS 下载原图
            List<Float> embedding = embeddingExtractor.extract(tempFile);
            pictureEmbeddingMapper.upsert(picture.getId(), picture.getSpaceId(), embedding);
        } catch (Exception e) {
            log.warn("写入图片向量失败（最终一致，不影响图片上传），pictureId={}", picture.getId(), e);
        } finally {
            deleteTempFile(tempFile);
        }
    }

    @Override
    public void onDelete(Picture picture) {
        try {
            pictureEmbeddingMapper.deleteByPictureId(picture.getId());
        } catch (Exception e) {
            log.warn("删除图片向量失败（最终一致），pictureId={}", picture.getId(), e);
        }
    }

    @Override
    public List<Long> search(File queryFile, Long spaceId, int topK) {
        List<Float> embedding = embeddingExtractor.extract(queryFile);
        return pictureEmbeddingMapper.searchSimilarPictureIds(embedding, spaceId, topK);
    }
}
```

**4.2 `ci` 策略** — `CiImageSearchStrategy.java`

```java
@Slf4j
@Component
@ConditionalOnProperty(prefix = "image-search", name = "strategy", havingValue = "ci")
public class CiImageSearchStrategy implements ImageSearchStrategy {

    @Resource private CosManager cosManager;

    @Override
    public void onUpload(Picture picture, UploadPictureResult result) {
        try {
            cosManager.addGalleryImage(result.getOriginalKey(), picture.getId()); // entityId 存 pictureId
        } catch (Exception e) {
            log.warn("CI 图库入库失败（最终一致，不影响图片上传），pictureId={}", picture.getId(), e);
        }
    }

    @Override
    public void onDelete(Picture picture) {
        try {
            String key = extractKey(picture.getUrl());
            if (key != null) {
                cosManager.deleteGalleryImage(key);
            }
        } catch (Exception e) {
            log.warn("CI 图库出库失败（最终一致），pictureId={}", picture.getId(), e);
        }
    }

    @Override
    public List<Long> search(File queryFile, Long spaceId, int topK) {
        String suffix = FileUtil.getSuffix(queryFile.getName());
        if (StrUtil.isBlank(suffix)) suffix = "jpg";
        String queryKey = "search/query/" + RandomUtil.randomString(16) + "." + suffix;
        cosManager.putObject(queryKey, queryFile); // CI 检索要求查询图位于 COS
        try {
            return cosManager.searchGalleryImages(queryKey, topK);
        } finally {
            try { cosManager.deleteObject(queryKey); } catch (Exception e) { log.warn(...); }
        }
    }
}
```

设计要点：

- 两个策略通过 `@ConditionalOnProperty` 保证同一时刻只有一个生效（`image-search.strategy=pg` 或 `ci`，缺省为 `pg`）。
- 策略的 `onUpload` / `onDelete` 内部均 try-catch 兜底，失败仅记日志，符合《事务设计文档》「副本缺失可容忍、可修复」的最终一致原则，不影响图片上传 / 删除主流程。
- `search` 统一返回 `List<Long>`（pictureId），屏蔽两种实现的差异；`ci` 策略入库时用 `entityId` 保存 `pictureId`，检索时由 CI 原样带回再解析。

> 依赖说明：`ci` 策略调用的是数据万象 CI 的「图像搜索」能力（对应 SDK 的 `addGalleryImages` / `searchGalleryImages`）。「图像搜索」属于数据万象「内容识别」分类下的能力，随内容识别一并开通；首次使用前需先调用 `openImageSearch` 建立图库（图库容量设置后不可修改）。该策略已通过真实 CI 端到端验证；考虑到费用与图库一次性容量，默认仍以 `pg` 策略为主。

```java
// 下载 COS 对象到本地文件（供 pg 策略提取向量用）
public void downloadObject(String key, File destFile) throws IOException {
    COSObject cosObject = cosClient.getObject(cosClientConfig.getBucket(), key);
    try (InputStream in = cosObject.getObjectContent();
         OutputStream out = new FileOutputStream(destFile)) {
        in.transferTo(out);
    }
}

// 开通 Bucket 以图搜图图库（一次性操作，图库容量设置后不可修改）
public void openImageSearch(String maxCapacity, String maxQps) {
    OpenImageSearchRequest request = new OpenImageSearchRequest();
    request.setBucketName(cosClientConfig.getBucket());
    request.setMaxCapacity(maxCapacity);
    request.setMaxQps(maxQps);
    cosClient.openImageSearch(request);
}

// 加入 CI 以图搜图图库，entityId 保存 pictureId
public void addGalleryImage(String key, long pictureId) {
    ImageSearchRequest request = new ImageSearchRequest();
    request.setBucketName(cosClientConfig.getBucket());
    request.setObjectKey(key);
    request.setEntityId(String.valueOf(pictureId));
    cosClient.addGalleryImages(request);
}

// 从 CI 图库移除图片（DeleteImage 请求体需携带 entityId）
public void deleteGalleryImage(String key, long pictureId) {
    ImageSearchRequest request = new ImageSearchRequest();
    request.setBucketName(cosClientConfig.getBucket());
    request.setObjectKey(key);
    request.setEntityId(String.valueOf(pictureId));
    cosClient.deleteGalleryImages(request);
}

// CI 以图搜图，返回相似 pictureId 列表
public List<Long> searchGalleryImages(String queryKey, int limit) {
    ImageSearchRequest request = new ImageSearchRequest();
    request.setBucketName(cosClientConfig.getBucket());
    request.setObjectKey(queryKey);
    request.setLimit(String.valueOf(limit));
    ImageSearchResponse response = cosClient.searchGalleryImages(request);
    List<Long> pictureIds = new ArrayList<>();
    if (response == null || response.getImageInfos() == null) return pictureIds;
    for (ImageInfos info : response.getImageInfos()) {
        if (StrUtil.isNotBlank(info.getEntityId())) {
            pictureIds.add(Long.valueOf(info.getEntityId()));
        }
    }
    return pictureIds;
}
```

设计要点：

- COS SDK 的 `addGalleryImages` 走 `ci-process=ImageSearch&action=AddImage`，XML 请求体只序列化 `EntityId` / `CustomContent` / `Tags` 三个字段；`searchGalleryImages` 返回的 `ImageInfos.entityId` 即入库时的 `pictureId`，实现「CI 检索结果 → pictureId」的映射。

以图搜图实现：

```java
@Override
public List<PictureVO> searchPictureByPicture(PictureSearchByPictureRequest request) {
    long userId = StpUtil.getLoginIdAsLong();
    Long spaceId = request.getSpaceId();
    int topK = request.getTopK() != null && request.getTopK() > 0
            ? request.getTopK() : PictureConstant.DEFAULT_SEARCH_TOP_K;

    // 空间图片需校验查看权限；公共图库所有登录用户可搜
    if (spaceId != null) {
        checkSpacePermission(spaceId, userId, SpaceUserConstant.PERMISSION_PICTURE_VIEW);
    }

    File queryFile = null;
    try {
        queryFile = resolveQueryFile(request); // 本地文件转存 或 URL 下载为临时文件
        List<Long> pictureIds = imageSearchStrategy.search(queryFile, spaceId, topK);
        if (pictureIds.isEmpty()) return List.of();
        // 回查 MySQL 详情，保留相似度顺序，并兜底过滤空间与已删除图片
        return listPictureVOByIds(pictureIds, spaceId);
    } finally {
        deleteTempFile(queryFile);
    }
}
```

辅助方法：

- `resolveQueryFile`：将 `MultipartFile` 转存或 `fileUrl` 下载为本地临时文件（保留原后缀）。
- `listPictureVOByIds`：按 `pictureIds` 回查 MySQL（`in` 查询 + `spaceId` 过滤），用 `Map` 按相似度顺序组装，并自动过滤已逻辑删除的图片。

事务顺序（遵循《事务设计文档》）：

- **上传**：COS 上传 → MySQL 写 `picture`（本地事务）→ PG 写向量 / CI 入库（事务外，最终一致）。
- **删除**：MySQL 逻辑删 → PG 删向量 / CI 出库 → COS 删对象（最终一致）。
- **以图搜图**：只读（PG/CI 检索 + MySQL 回查，以 MySQL 为准过滤）。

`CiImageSearchStrategyTest` 用 Mockito mock `CosManager`，验证 `ci` 策略的入库 / 出库 / 检索 / 临时对象清理逻辑，不依赖真实 CI 环境。

`CosImageSearchEndToEndTest` 真实调用腾讯云数据万象「图像搜索」接口，覆盖完整链路。因会产生真实费用与 COS/CI 副作用、且图库容量一次性不可改，默认通过 `@EnabledIfEnvironmentVariable` 跳过，需显式启用：

```powershell
$env:RUN_CI_E2E='true'; mvn -Dtest=CosImageSearchEndToEndTest test
```

## 四、问题修复记录

| 问题 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| PG 数据源属性绑定失败 | `jdbcUrl is required with driverClassName` | `@ConfigurationProperties` 直接绑定 Hikari 时，`url` 无法映射到 Hikari 的 `jdbcUrl` 字段 | 改用 `DataSourceProperties` + `initializeDataSourceBuilder()` 创建数据源 |

| Windows 控制台中文日志乱码 | 日志显示 `δ��¼��δ�ܶ�ȡ����Ч token` | JDK 17 默认 `file.encoding=GBK`，与 UTF-8 控制台不匹配；surefire 转发层还叠加了一层编码错位 | `pom.xml` 的 surefire `argLine` + spring-boot `jvmArguments` 设置 UTF-8；新增 `.mvn/jvm.config` 让 Maven 主进程也 UTF-8 |
