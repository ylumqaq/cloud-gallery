**`picture` 表结构**（本阶段新建，建表 SQL 位于 `resources/sql/mysql_schema.sql`）：

```sql
CREATE TABLE IF NOT EXISTS `picture` (
    `id`            BIGINT        NOT NULL COMMENT '图片 ID（雪花 ID）',
    `name`          VARCHAR(128)  NOT NULL COMMENT '图片名称',
    `url`           VARCHAR(1024) NOT NULL COMMENT '原图 URL（COS）',
    `thumbnail_url` VARCHAR(1024) NULL     COMMENT '缩略图 URL（COS）',
    `pic_size`      BIGINT        NULL     COMMENT '图片大小（字节）',
    `pic_width`     INT           NULL     COMMENT '图片宽度',
    `pic_height`    INT           NULL     COMMENT '图片高度',
    `pic_format`    VARCHAR(32)   NULL     COMMENT '格式：jpeg / png / jpg / webp',
    `pic_color`     VARCHAR(32)   NULL     COMMENT '平均主色调（用于按颜色搜索）',
    `category`      VARCHAR(128)  NULL     COMMENT '图片分类（用于分类分析）',
    `tags`          VARCHAR(512)  NULL     COMMENT '图片标签（JSON 数组字符串，用于标签分析）',
    `space_id`      BIGINT        NULL     COMMENT '所属空间 ID（空 = 公共图库）',
    `user_id`       BIGINT        NOT NULL COMMENT '上传者 / 作者用户 ID',
    `create_time`   DATETIME      NOT NULL COMMENT '创建时间',
    `edit_time`     DATETIME      NULL     COMMENT '最近编辑时间',
    `update_time`   DATETIME      NOT NULL COMMENT '更新时间',
    `is_delete`     TINYINT       NOT NULL DEFAULT 0 COMMENT '逻辑删除：0 未删除 / 1 已删除',
    PRIMARY KEY (`id`),
    KEY `idx_picture_space_id` (`space_id`),
    KEY `idx_picture_user_id` (`user_id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT = '图片表';
```

| `category` | VARCHAR(128) | 图片分类（用于分类分析） |
| `tags` | VARCHAR(512) | 图片标签（JSON 数组字符串，用于标签分析） |
| `space_id` | BIGINT | 所属空间 ID（空 = 公共图库） |

### 4. 上传模板（模板方法模式）

文件位于 `manager/upload/`：

| 文件 | 说明 |
| --- | --- |
| `PictureUploadTemplate.java` | 抽象模板，统一上传骨架：校验 → 生成对象键 → 获取本地文件 → 上传 COS → CI 处理 → 封装结果 → 清理临时文件 |
| `FilePictureUpload.java` | 本地文件上传：校验大小 ≤ 2MB、格式，转存临时文件 |

模板方法三个抽象差异化步骤：`validPicture()`、`getOriginalFilename()`、`processFile()`。

### 5. COS + CI 封装

| 文件 | 说明 |
| --- | --- |
| `config/CosClientConfig.java` | 读取 `cos.*` 配置，初始化 `COSClient` |
| `manager/CosManager.java` | `putObject`（上传）、`processImage`（CI 云上数据处理）、`getObjectUrl`、`deleteObject` |

CI 处理采用「云上数据处理」方式：先 `putObject` 上传原图，再 `processImage` 触发 webp 压缩 + 缩略图生成 + 返回原图信息（宽高 / 格式 / 主色调）。每条处理规则需设置 `bucket`，`fileid` 使用原图同目录下的简单文件名。

对象键规则：`{prefix}/{yyyyMMdd}/{uuid}.{suffix}`；webp 为 `{uuid}_webp.webp`；缩略图为 `{uuid}_thumbnail.{suffix}`。上传路径前缀：公共图库 `public`，空间 `space/{spaceId}`。

### 6. 图片服务层 + 控制层

文件：`service/PictureService.java`、`service/impl/PictureServiceImpl.java`、`controller/PictureController.java`（前缀 `/picture`）

| 接口 | 方法 | 权限 | 说明 |
| --- | --- | --- | --- |
| `/picture/upload` | POST | 登录 + `@SaSpaceCheckPermission(picture:upload)` | 本地 / URL 上传 |
| `/picture/list/page/vo` | GET | 登录 | 分页查询（公共图库可看，空间按权限） |
| `/picture/get/{id}` | GET | 登录 | 图片详情 |
| `/picture/edit` | POST | 登录（Service 层校验） | 改名 + 移动空间 |
| `/picture/delete` | POST | 登录（Service 层校验） | 删除（逻辑删 MySQL + 删 COS） |
| `/picture/upload/batch` | POST | 登录 | 批量抓取上传（Jsoup 爬必应图片搜索） |

关键事务顺序（遵循《事务设计文档》）：

- **上传**：先 COS 后 MySQL；MySQL 写入失败时补偿删除 COS 对象，上传阶段异常时补偿删除原图。
- **删除**：先逻辑删 MySQL，再删 COS 原图 / 缩略图 / webp 图；COS 删除失败仅产生孤儿对象，不影响业务。

### 7. 权限设计

- **上传**：由 `@SaSpaceCheckPermission(picture:upload)` 切面基于 `request.spaceId` 校验。
- **详情 / 编辑 / 删除**：因 `id` 无法被切面解析出 `spaceId`，在 Service 层通过 `checkPicturePermission` 手动校验：
  - 公共图库图片（`space_id` 为空）：仅图片上传者本人可编辑 / 删除；
  - 空间图片（`space_id` 非空）：按空间角色权限码校验（viewer / editor / admin）。

## 三、问题修复记录

| 问题 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| COS 签名缺失 | `403 AccessDenied: Auth sign header must include Pic-Operations` | `cos_api 5.6.155` 的 `COSSigner` 未将 `Pic-Operations` 头纳入签名 | 升级 `cos_api` 至 `5.6.227` |
| CI 参数无效 | `400 InvalidPicOperations: Pic operations param invalid` | 云上数据处理每条 `Rule` 需指定 `bucket` | 为每条处理规则设置 `bucket` |
| 公共图库无法编辑 / 删除 | 返回 `40101 无空间权限` | 公共图库权限码仅 `picture:view/upload`，无 `edit/delete` | Service 层对公共图库图片按「仅上传者可操作」处理 |
