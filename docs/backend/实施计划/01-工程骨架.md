# 阶段 1：工程骨架

## 一、目标

搭建可运行的 Spring Boot 3.5.16 工程，建立统一的工程目录与 Maven 依赖管理，完成统一返回、统一异常处理，并初始化 MySQL / PostgreSQL 表结构。本阶段是后续所有模块的基础，不涉及具体业务接口。

## 二、前置依赖

无。仅需本机已就绪以下环境（详见《环境部署文档》）：

| 依赖 | 版本要求 | 用途 |
| --- | --- | --- |
| JDK | 17 | 编译与运行（`JAVA_HOME` 指向 17） |
| Maven | 3.9+ | 构建与依赖管理 |
| MySQL | 8.0 | 业务库（端口 3306） |
| PostgreSQL | 18 + pgvector | 向量库（端口 5432） |
| Redis | 5.0+ | 会话 / 缓存（端口 6379） |

## 三、创建 Maven 工程

### 3.1 工程坐标与基本信息

| 项 | 建议值 | 说明 |
| --- | --- | --- |
| groupId | `com.ylum` | 组织 / 域名反写 |
| artifactId | `cloud-gallery` | 模块名 |
| version | `1.0.0` | 初始版本 |
| packaging | `jar` | 打成可执行 jar |
| parent | `spring-boot-starter-parent:3.5.16` | 统一管理 Spring Boot 依赖版本 |
| 启动类包名 | `com.ylum.cloudgallery` | 主包，后续代码均在其下 |

创建方式二选一：

1. **手动创建**（推荐，依赖多、需精细控制）：直接新建 `pom.xml` + 目录结构（见 3.2、3.3），再用 IDE（IDEA）导入为 Maven 工程。
2. **Spring Initializr**（https://start.spring.io）：选 Maven / Java 17 / Spring Boot 3.5.16，勾选 Web、MyBatis、Redis 等基础依赖后生成，再补其余依赖。

> 无论哪种方式，最终 `pom.xml` 均需与 3.3 节对齐。

## 六、关键类设计

### 1. BaseResponse<T>（统一返回对象）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 状态码（0 成功，非 0 失败） |
| data | T | 业务数据（可为 null） |
| message | String | 提示信息 |

```java
/**
 * 统一返回对象，所有接口返回 BaseResponse<T> 结构
 */
@Data
public class BaseResponse<T> {
    private int code;       // 状态码
    private T data;         // 业务数据
    private String message; // 提示信息

    public BaseResponse(int code, T data, String message) {
        this.code = code;
        this.data = data;
        this.message = message;
    }
}
```

### 2. ResultUtils（统一返回工具）

提供静态工厂方法，避免控制器内重复 `new BaseResponse(...)`：

- `success(T data)`：成功 + 数据
- `success()`：成功（无数据）
- `error(int code, String message)`：指定错误码与信息
- `error(ErrorCode errorCode)`：按错误码枚举构造
- `error(ErrorCode errorCode, String message)`：按错误码枚举 + 覆盖信息

### 3. ErrorCode（错误码枚举）

对齐 API 文档「二、错误码」表：

| 枚举 | code | 说明 |
| --- | --- | --- |
| SUCCESS | 0 | 成功 |
| PARAMS_ERROR | 40000 | 请求参数错误 |
| NOT_LOGIN_ERROR | 40100 | 未登录 |
| NO_AUTH_ERROR | 40101 | 无权限 |
| FORBIDDEN_ERROR | 40300 | 禁止访问 |
| NOT_FOUND_ERROR | 40400 | 请求数据不存在 |
| SYSTEM_ERROR | 50000 | 系统内部异常 |
| OPERATION_ERROR | 50001 | 操作失败 |

```java
/**
 * 错误码枚举，统一管理业务错误码与提示信息
 */
@Getter
public enum ErrorCode {
    SUCCESS(0, "ok"),
    PARAMS_ERROR(40000, "请求参数错误"),
    NOT_LOGIN_ERROR(40100, "未登录"),
    NO_AUTH_ERROR(40101, "无权限"),
    FORBIDDEN_ERROR(40300, "禁止访问"),
    NOT_FOUND_ERROR(40400, "请求数据不存在"),
    SYSTEM_ERROR(50000, "系统内部异常"),
    OPERATION_ERROR(50001, "操作失败");

    private final int code;    // 错误码
    private final String message; // 默认提示信息

    ErrorCode(int code, String message) {
        this.code = code;
        this.message = message;
    }
}
```

### 4. BusinessException（业务异常）

```java
/**
 * 业务异常，抛出时携带错误码与提示信息，由全局异常处理器统一捕获
 */
@Getter
public class BusinessException extends RuntimeException {
    private final int code; // 错误码

    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }

    public BusinessException(ErrorCode errorCode) {
        super(errorCode.getMessage());
        this.code = errorCode.getCode();
    }

    public BusinessException(ErrorCode errorCode, String message) {
        super(message);
        this.code = errorCode.getCode();
    }
}
```

### 5. GlobalExceptionHandler（全局异常处理器）

`@RestControllerAdvice` 统一捕获并转为 `BaseResponse`，处理规则：

| 异常 | 处理结果 |
| --- | --- |
| `BusinessException` | 返回业务 code + message |
| 参数校验异常（`MethodArgumentNotValidException` / `ConstraintViolationException`） | 返回 40000 |
| Sa-Token `NotLoginException` | 返回 40100 |
| Sa-Token `NotPermissionException` / `NotRoleException` | 返回 40101 |
| 兜底 `Exception` | 返回 50000 |

```java
/**
 * 全局异常处理器：统一将异常转为 BaseResponse
 */
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public BaseResponse<?> businessExceptionHandler(BusinessException e) {
        log.error("BusinessException: {}", e.getMessage());
        return ResultUtils.error(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public BaseResponse<?> methodArgumentNotValidExceptionHandler(MethodArgumentNotValidException e) {
        // 取第一条校验错误信息返回
        String message = e.getBindingResult().getFieldErrors().stream()
                .map(FieldError::getDefaultMessage)
                .findFirst()
                .orElse(ErrorCode.PARAMS_ERROR.getMessage());
        return ResultUtils.error(ErrorCode.PARAMS_ERROR.getCode(), message);
    }

    @ExceptionHandler(Exception.class)
    public BaseResponse<?> exceptionHandler(Exception e) {
        log.error("RuntimeException", e);
        return ResultUtils.error(ErrorCode.SYSTEM_ERROR);
    }
}
```

> 说明：Sa-Token 的 `NotLoginException` / `NotPermissionException` / `NotRoleException` 可在阶段 2 引入 Sa-Token 后补充对应 `@ExceptionHandler`，本阶段先完成 `BusinessException` + 兜底 `Exception` 即可。
