# 阶段 7：空间分析与其他 —— 接口测试

> 本手册用于阶段 7 空间分析 / 按颜色搜索 / 多级缓存的手动接口测试与回归验证，配套自动化测试见文末「八、自动化测试」。
> 所有接口均以 `/api` 为上下文路径，登录态通过请求头 `satoken` 传递 token。

## 一、测试范围与约定

- 范围：
  - 空间分析（使用 / 分类 / 标签 / 大小 / 排行）；
  - 按颜色搜索（主色调 hex 转 RGB + 欧氏距离排序）；
  - 多级缓存（Caffeine 本地一级 + Redis 二级）。
- 统一返回结构：

```json
{ "code": 0, "data": null, "message": "ok" }
```

- 错误码约定：

| 错误码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 40000 | 请求参数错误 |
| 40100 | 未登录 |
| 40101 | 无权限 |
| 40300 | 禁止访问 |
| 40400 | 请求数据不存在 |
| 50000 | 系统内部异常 |

- 空间上限常量（`SpaceConstant`，全局统一，后续调整只需改常量）：

| 常量 | 默认值 | 说明 |
| --- | --- | --- |
| `DEFAULT_MAX_PICTURE_COUNT` | 400 | 单个空间最大图片数量（张） |
| `DEFAULT_MAX_PICTURE_SIZE` | 500MB（524288000 字节） | 单个空间最大图片总大小 |

- 空间分析接口的 `spaceId` 为空表示统计公共图库；为空/非空由 ShardingSphere 路由到 `picture` 或 `picture_{spaceId}` 物理表。

## 二、测试环境准备

1. 启动 MySQL（库名 `cloud_gallery`，`picture` 表需含 `category`、`tags` 字段）。
2. 启动 Redis（端口 6379，缓存测试依赖）。
3. 在 `application.yml` 配置真实 COS 密钥（上传图片会真实写入 COS）。
4. 启动服务：端口 8123，上下文路径 `/api`。

```powershell
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-17.0.19.10-hotspot'
mvn spring-boot:run
```

启动成功标志（日志）：

```
ShardingSphere-JDBC Standalone mode started successfully.
Tomcat started on port 8123 (http) with context path '/api'
```

> 说明：若 `picture` 表在阶段 7 之前已存在，需先执行字段迁移（新空间通过 `CREATE TABLE ... LIKE picture` 自动继承新字段）：
>
> ```sql
> ALTER TABLE picture
>   ADD COLUMN category VARCHAR(128) NULL COMMENT '图片分类（用于分类分析）' AFTER pic_color,
>   ADD COLUMN tags VARCHAR(512) NULL COMMENT '图片标签（JSON 数组字符串，用于标签分析）' AFTER category;
> ```

## 三、登录态获取（前置）

注册并登录，从登录响应 `data.token` 中取出 token，后续请求放入请求头 `satoken`。

```powershell
$base = "http://localhost:8123/api"

# 1. 注册
Invoke-RestMethod -Uri "$base/user/register" -Method Post -ContentType "application/json" `
  -Body '{"userAccount":"analyze_tester","userPassword":"12345678","checkPassword":"12345678"}'

# 2. 登录，获取 token
$login = Invoke-RestMethod -Uri "$base/user/login" -Method Post -ContentType "application/json" `
  -Body '{"userAccount":"analyze_tester","userPassword":"12345678"}'
$token = $login.data.token
```

上传图片（本地文件用 curl.exe 处理 multipart 更便捷）：

```powershell
# 上传到公共图库（不传 spaceId）
curl.exe -X POST "$base/picture/upload" -H "satoken: $token" `
  -F "file=@C:\path\to\test.png" -F "picName=测试图片" -F "category=头像" -F "tags=[\"风景\",\"旅行\"]"
```

> 提示：空间用量排行需要系统管理员账号。可将某用户升级为管理员后重新登录：
>
> ```sql
> UPDATE `user` SET user_role = 'admin' WHERE user_account = 'analyze_tester';
> ```

## 四、空间分析测试用例

### 1. 空间使用分析

`GET /api/space/analyze/usage`，权限：登录 + 空间查看权限（`picture:view`）。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| spaceId | long | 空间 ID（空 = 公共图库） |

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-ANALYZE-001 | 公共图库使用分析 | 上传 2 张图片到公共图库后 `GET /space/analyze/usage`（spaceId 缺省） | code=0，`usedCount=2`、`usedSize` 为两张图片总大小、`maxCount=400`、`maxSize=524288000` |
| TC-ANALYZE-002 | 指定空间使用分析 | 创建空间并上传图片后 `GET /space/analyze/usage?spaceId={spaceId}` | code=0，仅统计该空间图片 |
| TC-ANALYZE-003 | 未登录 | 不带 token | code=40100 |

### 2. 分类分析

`GET /api/space/analyze/category`，权限：登录 + 空间查看权限（`picture:view`）。

| 参数 | 类型 | 说明 |

| spaceId | long | 空间 ID（空 = 公共图库） |

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-ANALYZE-004 | 分类分组统计 | 上传 category=头像（2 张）、category=壁纸（1 张）后查询 | code=0，返回 2 个分组；头像组 `count=2` 排在首位，各组含 `category/count/totalSize` |
| TC-ANALYZE-005 | 未分类图片归入「未分类」 | 上传不带 category 的图片后查询 | 返回分组含 `category=未分类` |

## 五、按颜色搜索测试用例

`GET /api/picture/search/color`，权限：登录（公共图库可搜，空间图片按权限）。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| picColor | string | 目标主色调（十六进制，如 `0xff0000`） |
| spaceId | long | 空间 ID（空 = 公共图库） |
| topN | int | 返回相近图片数量，默认 20 |

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-COLOR-001 | 相近颜色排序 | 上传红色（`0xff0000`）、蓝色（`0x0000ff`）图片后，`GET /picture/search/color?picColor=0xff0000` | code=0，返回按颜色距离升序，红色图片排在蓝色之前 |
| TC-COLOR-002 | 颜色格式非法 | `picColor=xyz` | code=40000 |
| TC-COLOR-003 | 未登录 | 不带 token | code=40100 |

> 说明：上传图片时主色调由数据万象 CI 提取（如纯红为 `0xff0000` 或 `0xe00000` 等），实测颜色值以 CI 返回为准；搜索时按 RGB 欧氏距离排序，距离越小越靠前。

## 六、多级缓存测试用例

`GET /api/cache/test`，权限：无（演示 Caffeine + Redis 两级缓存）。

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-CACHE-001 | 缓存命中 | 连续两次 `GET /cache/test` | 两次 code=0，且返回的 `data`（含时间戳）一致，说明第二次命中缓存未重新执行方法体 |
| TC-CACHE-002 | Redis 缓存落盘 | 首次调用后查看 Redis key | Redis 存在 `cache:cache:test:value`，值为 JSON 字符串 |

### 2. 缓存核对

```powershell
# 使用 redis-cli 查看（若配置了密码需加 -a）
redis-cli KEYS "cache:cache:test:*"
redis-cli GET "cache:cache:test:value"
```

预期：首次调用 `/cache/test` 后，Redis 中存在 `cache:cache:test:value`；本地 Caffeine 命中后仍返回相同时间戳。

## 八、自动化测试

已提供 JUnit 自动化测试，覆盖空间分析、按颜色搜索与缓存接口核心逻辑：

| 测试类 | 类型 | 用例数 | 对应范围 |
| --- | --- | --- | --- |
| `SpaceAnalyzeControllerTest` | 集成测试（MockMvc，真实 MySQL + Redis） | 7 | usage / category / tag / size / rank 权限 / 颜色搜索 / 缓存接口 |
| `ColorSimilarUtilsTest` | 单元测试 | 6 | hex 转 RGB（三种前缀）、欧氏距离、非法颜色异常 |

运行命令（需 MySQL、Redis 已启动）：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-17.0.19.10-hotspot'
mvn test "-Dtest=SpaceAnalyzeControllerTest,ColorSimilarUtilsTest"
```

测试文件位置：

- `src/test/java/com/ylum/cloudgallery/controller/SpaceAnalyzeControllerTest.java`
- `src/test/java/com/ylum/cloudgallery/utils/ColorSimilarUtilsTest.java`

> 注意：
> - `SpaceAnalyzeControllerTest` 通过 `PictureMapper` 直接插入公共图库测试图片（不依赖 COS 上传），并开启 `@Transactional` 自动回滚，避免污染数据库。
> - 缓存接口测试不依赖登录态，但 Redis 中的缓存 key 不会随事务回滚；如需重复运行，可先执行 `redis-cli FLUSHDB` 清空 Redis。
