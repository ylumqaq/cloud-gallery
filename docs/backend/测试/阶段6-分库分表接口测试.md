# 阶段 6：分库分表 —— 接口测试

> 本手册用于阶段 6 分库分表的手动接口测试与回归验证，配套自动化测试见文末「七、自动化测试」。
> 所有接口均以 `/api` 为上下文路径，登录态通过请求头 `satoken` 传递 token。
> 分库分表**不新增接口**，而是验证现有「空间创建 / 图片上传 / 图片查询」接口在 ShardingSphere 分片下的路由行为。

## 一、测试范围与约定

- 范围：按 `space_id` 分表后的自动建表、写入路由、查询路由、跨空间隔离，以及动态建表后的规则刷新。
- 统一返回结构：

```json
{ "code": 0, "data": null, "message": "ok" }
```

- 错误码约定：

| 错误码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 40000 | 请求参数错误 |
| 40100 | 未登录 |
| 40101 | 无权限 |
| 40300 | 禁止访问 |
| 40400 | 请求数据不存在 |
| 50000 | 系统内部异常 |

- 分片路由规则（本阶段核心）：

| 场景 | `space_id` | 物理表 |
| --- | --- | --- |
| 公共图库 | 空 | `picture` |
| 私有 / 团队空间 | 非空 | `picture_{space_id}` |

- 单表规则：`user` / `space` / `space_user` 不分片，由 ShardingSphere `SINGLE` 规则路由到唯一物理数据源 `cloud_gallery`。
- 动态建表：空间创建成功时执行 `CREATE TABLE picture_{space_id} LIKE picture`，并运行时刷新分片规则。

## 二、测试环境准备

1. 启动 MySQL（库名 `cloud_gallery`，含 `picture`、`user`、`space`、`space_user` 四张表）。
2. 启动 Redis（端口 6379）。
3. 在 `application.yml` 配置真实 COS 密钥（上传图片会真实写入 COS）。
4. `pom.xml` 已引入 ShardingSphere 分片依赖（`sharding-core` / `parser-sql-engine-mysql` / `standalone-mode-*` 等）。
5. 启动服务：端口 8123，上下文路径 `/api`。

```powershell
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-17.0.19.10-hotspot'
mvn spring-boot:run
```

启动成功标志（日志）：

```
ShardingSphere-JDBC Standalone mode started successfully.
Tomcat started on port 8123 (http) with context path '/api'
```

## 三、登录态获取（前置）

注册并登录，从登录响应 `data.token` 中取出 token，后续请求放入请求头 `satoken`。

```powershell
$base = "http://localhost:8123/api"

# 1. 注册
Invoke-RestMethod -Uri "$base/user/register" -Method Post -ContentType "application/json" `
  -Body '{"userAccount":"shard_tester","userPassword":"12345678","checkPassword":"12345678"}'

# 2. 登录，获取 token
$login = Invoke-RestMethod -Uri "$base/user/login" -Method Post -ContentType "application/json" `
  -Body '{"userAccount":"shard_tester","userPassword":"12345678"}'
$token = $login.data.token
```

创建空间 / 图片上传使用如下方式：

```powershell
# 创建团队空间
Invoke-RestMethod -Uri "$base/space/add" -Method Post -Headers @{ satoken = $token } `
  -ContentType "application/json" -Body '{"spaceName":"分片测试空间","spaceType":1}'

# 上传图片（本地文件用 curl.exe 处理 multipart 更便捷）
curl.exe -X POST "$base/picture/upload" -H "satoken: $token" -F "file=@C:\path\to\test.png" -F "spaceId=123"
```

## 四、分库分表测试用例

### 1. 自动建表用例

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-SHARD-001 | 创建团队空间自动建表 | 登录后 `POST /space/add`（spaceType=1） | code=0 返回 spaceId；数据库自动生成 `picture_{spaceId}` |
| TC-SHARD-002 | 创建私有空间自动建表 | 登录后 `POST /space/add`（spaceType=0） | code=0 返回 spaceId；数据库自动生成 `picture_{spaceId}`（私有空间同样按 space_id 分表） |

> 数据库核对（见「五、数据库核对」）：`SHOW TABLES LIKE 'picture%'` 应能看到 `picture` 与新建的 `picture_{spaceId}`。

### 2. 写入路由用例

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-SHARD-003 | 空间图片写入分表 | 上传图片到空间（spaceId 非空） | code=0；该记录写入 `picture_{spaceId}`，而非 `picture` |
| TC-SHARD-004 | 公共图库写入主表 | 上传图片到公共图库（spaceId 缺省） | code=0；该记录写入 `picture` 表 |

> 数据库核对：上传空间图片后，
> - `SELECT COUNT(*) FROM picture WHERE space_id={spaceId}` 应为 0；
> - `SELECT COUNT(*) FROM picture_{spaceId} WHERE space_id={spaceId}` 应为 1。

### 3. 查询路由用例

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-SHARD-005 | 空间图片查询 | `GET /picture/list/page/vo?spaceId={spaceId}` | code=0，返回空间内图片（从分表读取） |
| TC-SHARD-006 | 公共图库查询 | `GET /picture/list/page/vo`（spaceId 缺省） | code=0，仅返回公共图库图片（从 `picture` 读取） |
| TC-SHARD-007 | 图片详情 | `GET /picture/get/{id}` | code=0，返回对应图片（按 id 路由到所属分表） |

### 4. 跨空间隔离用例

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-SHARD-008 | 公共图库与空间隔离 | 公共图库上传 1 张、空间 A 上传 1 张后分别查询 | 公共图库查询只返回公共图，空间查询只返回空间图，互不串数据 |
| TC-SHARD-009 | 空间 A 与空间 B 隔离 | 创建空间 A、B，各自上传图片后分别查询 | 空间 A 查询只返回 A 的图片，空间 B 查询只返回 B 的图片 |

### 5. 动态刷新规则用例

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-SHARD-010 | 新建空间后立即可用 | 创建空间 A 上传图片成功后，再创建空间 B 并上传图片 | 空间 B 无需重启服务即可正常建表并写入 / 查询（规则已动态刷新） |
| TC-SHARD-011 | 连续建多个空间 | 依次创建 3 个空间并各自上传图片 | 每张图片都路由到各自 `picture_{spaceId}`，无「表不存在」报错 |

## 五、数据库核对

测试过程中可用 MySQL 客户端直接核对物理分表与数据落位。

```powershell
$mysql = 'C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe'
```

查看当前所有图片物理表：

```sql
USE cloud_gallery;
SHOW TABLES LIKE 'picture%';
-- 预期：picture（公共） + picture_{spaceId1} + picture_{spaceId2} + ...
```

核对空间图片落位：

```sql
-- 空间图片应只落在分表
SELECT COUNT(*) AS public_cnt FROM picture WHERE space_id = {spaceId};       -- 期望 0
SELECT COUNT(*) AS shard_cnt FROM picture_{spaceId} WHERE space_id = {spaceId}; -- 期望 1
```

查看分表结构是否与主表一致：

```sql
SHOW CREATE TABLE picture_{spaceId};
-- 结构应与 picture 一致（由 CREATE TABLE ... LIKE picture 生成）
```

## 六、权限说明

- 空间创建 / 图片上传 / 图片查询接口的鉴权逻辑**不因分表而改变**：
  - 创建空间：登录即可；
  - 上传图片：登录 + `@SaSpaceCheckPermission(picture:upload)`；
  - 查询空间图片：登录 + 空间 `picture:view` 权限；
  - 公共图库查询：所有登录用户可看。
- 分表仅改变数据存储位置，不改变权限边界。
