**`user` 表结构**（建表 SQL）：

```sql
CREATE TABLE IF NOT EXISTS `user` (
    `id`            BIGINT        NOT NULL COMMENT '用户 ID（雪花 ID）',
    `user_account`  VARCHAR(256)  NOT NULL COMMENT '登录账号',
    `user_password` VARCHAR(512)  NOT NULL COMMENT '密码（加密存储）',
    `user_name`     VARCHAR(256)  NULL     COMMENT '昵称',
    `user_avatar`   VARCHAR(1024) NULL     COMMENT '头像 URL',
    `user_profile`  VARCHAR(512)  NULL     COMMENT '个人简介',
    `user_role`     VARCHAR(64)   NOT NULL DEFAULT 'user' COMMENT '用户角色（user / admin）',
    `create_time`   DATETIME      NOT NULL COMMENT '创建时间',
    `update_time`   DATETIME      NOT NULL COMMENT '更新时间',
    `is_delete`     TINYINT       NOT NULL DEFAULT 0 COMMENT '逻辑删除：0 未删除 / 1 已删除',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_user_account` (`user_account`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT = '用户表';
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT | 主键，雪花 ID（应用层生成） |
| `user_account` | VARCHAR(256) | 登录账号，唯一索引 |
| `user_password` | VARCHAR(512) | 密码（BCrypt 加密存储） |
| `user_name` | VARCHAR(256) | 昵称 |
| `user_avatar` | VARCHAR(1024) | 头像 URL |
| `user_profile` | VARCHAR(512) | 个人简介 |
| `user_role` | VARCHAR(64) | 用户角色（user / admin），默认 `user` |
| `create_time` | DATETIME | 创建时间（插入时自动填充） |
| `update_time` | DATETIME | 更新时间（插入 / 更新时自动填充） |
| `is_delete` | TINYINT | 逻辑删除：0 未删除 / 1 已删除，默认 0 |

### 4. 服务层

文件：`service/UserService.java`、`service/impl/UserServiceImpl.java`

关键实现：

- **注册**：校验两次密码一致 → 账号唯一性校验 → `BCrypt.hashpw` 加密 → 默认角色 `user` 入库。
- **登录**：按账号查询 → `BCrypt.checkpw` 校验密码（错误统一提示，避免暴露账号是否存在）→ `StpUtil.login(userId)` 写入登录态 → 返回脱敏信息 + token。
- **获取当前用户**：`StpUtil.getLoginIdAsLong()` → `getById` → 复制为 `UserVO` 脱敏返回。
- **退出**：`StpUtil.logout()` 清除会话。

### 6. 鉴权配置

文件：`config/SaTokenConfig.java`

- 注册 `SaInterceptor` 开启注解式鉴权，拦截 `/**`，使 `@SaCheckLogin` 生效。

文件：`common/GlobalExceptionHandler.java`（阶段 2 补充）

- 新增 `NotLoginException` → 40100、`NotPermissionException` / `NotRoleException` → 40101 的异常处理。

**技术选型**：Sa-Token（第三方 Java 鉴权框架，Maven 依赖引入，groupId `cn.dev33`），登录态存储于 Redis。

**依赖**（`pom.xml`）：

| 依赖 | 作用 |
| --- | --- |
| `sa-token-spring-boot3-starter` | Sa-Token 核心 + Spring Boot 3 自动装配，提供 `StpUtil`、`SaInterceptor`、`@SaCheckLogin` 等 |
| `sa-token-redis-jackson` | 登录态 / 会话持久化到 Redis（jackson 序列化） |

**鉴权原理（注解式鉴权）**：

1. **建立登录态**：登录成功时 `StpUtil.login(userId)` 在 Redis 写入会话记录（token → userId），并将 token 返回给前端。
2. **拦截器自动执行**：`SaTokenConfig` 注册的 `SaInterceptor`（Spring MVC 拦截器）拦截 `/**`，由 Spring 在请求到达 Controller 前自动调用其 `preHandle`。
3. **读取注解**：`SaInterceptor` 通过反射读取目标方法上的 `@SaCheckLogin` 注解，判断该接口是否需要登录。
4. **校验会话**：存在注解则调用 `StpUtil.checkLogin()`，根据请求携带的 token 到 Redis 校验对应会话；未登录抛 `NotLoginException`，由 `GlobalExceptionHandler` 统一转为 40100（无权限 / 无角色转为 40101）。

> 注解本身不包含逻辑，仅作「标记」；真正的校验逻辑由 `SaInterceptor` 实现，并依赖 Spring 拦截器机制在请求前自动触发。之所以需要 token + Redis 会话，是因为 HTTP 无状态——服务器无法天然识别请求来源，需凭 token 到 Redis 校验会话确认身份。

**未登录异常的来源**：

`NotLoginException` 是 Sa-Token 框架自身定义的异常（包名 `cn.dev33.satoken.exception`），由 `StpUtil.checkLogin()` 内部在会话不存在（未登录 / 已退出 / 过期）时抛出。本项目不负责抛出，只负责捕获并转换。

| 环节 | 谁写的 | 位置 |
| --- | --- | --- |
| 抛 `NotLoginException` | Sa-Token 包 | `StpUtil.checkLogin()` 内部 |
| 捕获并转 40100 | 本项目 | `GlobalExceptionHandler` |
