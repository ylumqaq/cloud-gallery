# 云图库分库分表专项设计文档

## 一、分片方案

- 分片键：`space_id`
- 逻辑表：`picture`
- 路由规则：
  - `space_id` 为空（公共图库）→ 落 `picture` 表
  - `space_id` 非空（团队空间）→ 落 `picture_{space_id}` 表
- 分片方式：标准分片（`StandardShardingAlgorithm`），仅需精确分片（`space_id = ?` 等值查询）

## 二、自定义分片算法

`PictureShardingAlgorithm` 实现 `StandardShardingAlgorithm<Long>`：

```java
public class PictureShardingAlgorithm implements StandardShardingAlgorithm<Long> {

    // 精确分片：根据 space_id 决定落到哪张物理表
    @Override
    public String doSharding(Collection<String> availableTargetNames,
                             PreciseShardingValue<Long> shardingValue) {
        Long spaceId = shardingValue.getValue();
        String logicTable = shardingValue.getLogicTableName();
        // 公共图库（spaceId 为空）落到逻辑表 picture，否则落到 picture_{spaceId}
        if (spaceId == null) {
            return logicTable;
        }
        return logicTable + "_" + spaceId;
    }

    // 范围分片业务不需要，返回空集合
    @Override
    public Collection<String> doSharding(Collection<String> availableTargetNames,
                                         RangeShardingValue<Long> shardingValue) {
        return Collections.emptyList();
    }
}
```

## 三、动态建表

团队空间创建时，动态创建对应的物理表：

```sql
CREATE TABLE picture_{spaceId} LIKE picture;
```

## 四、动态刷新分片规则

`DynamicShardingManager` 负责：

1. 扫描所有团队空间，动态生成 `actual-data-nodes`：

```
cloud_gallery.picture, cloud_gallery.picture_1, cloud_gallery.picture_2, ...
```

2. 团队空间创建时触发建表；
3. 通过 ShardingSphere 的 `ContextManager` 在运行时更新分片规则：

```java
// 构建新的分片规则配置（含 actualDataNodes）
ShardingRuleConfiguration ruleConfig = buildRuleConfig(allSpaceIds);
// 运行时刷新规则
contextManager.alterRuleConfiguration("sharding_db", ruleConfig);
```

> 注：具体 API 以 ShardingSphere 5.5.3 实际版本为准。

## 五、配置示例（application.yml）

```yaml
spring:
  shardingsphere:
    mode:
      type: Memory
    rules:
      sharding:
        tables:
          picture:
            actual-data-nodes: cloud_gallery.picture
            table-strategy:
              standard:
                sharding-column: space_id
                sharding-algorithm-name: picture-sharding
        sharding-algorithms:
          picture-sharding:
            type: CLASS_BASED
            props:
              strategy: STANDARD
              algorithmClassName: com.ylum.cloudgallery.manager.sharding.PictureShardingAlgorithm
```

## 六、注意事项

1. **主键不能用自增**：分表后各表自增会冲突，统一使用雪花 ID（`ASSIGN_ID`）。
2. **跨空间查询会广播**：不带 `space_id` 的查询会落到所有分表（全表扫描），此类查询需限制或用汇总表/搜索引擎承接。
3. **建表要保证结构一致**：`picture_{spaceId}` 与 `picture` 结构必须完全一致。
4. **动态规则与建表要原子化**：先建表、再刷新规则，避免路由到不存在的表。建表与刷规则在业务事务外顺序执行（单库分表复用本地事务，无需分布式事务），详见《事务设计文档》。
