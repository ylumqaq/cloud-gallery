# 云图库数据库设计文档

## 一、概述

- 业务库：MySQL 8.0.42（业务数据）
- 向量库：PostgreSQL 18.3 + pgvector（图片特征向量）
- 命名规范：表名/字段名小写下划线，通过 MyBatis-Plus 与 Java 驼峰自动映射
- 主键策略：统一 `BIGINT` + 雪花 ID（`ASSIGN_ID`），分表场景下避免自增 ID 冲突
- 逻辑删除：业务表统一 `is_delete` 字段（0 未删除 / 1 已删除）

## 二、MySQL 表设计

### 1. user 用户表

用户模块（注册/登录/脱敏）的核心表，保存用户账号与基本信息。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | 主键 | 用户 ID（雪花 ID） |
| user_account | VARCHAR(256) | 唯一索引 | 登录账号 |
| user_password | VARCHAR(512) | 非空 | 密码（加密存储） |
| user_name | VARCHAR(256) | 可空 | 昵称 |
| user_avatar | VARCHAR(1024) | 可空 | 头像 URL |
| user_profile | VARCHAR(512) | 可空 | 个人简介 |
| user_role | VARCHAR(64) | 默认 'user' | 用户角色（user / admin） |
| create_time | DATETIME | 非空 | 创建时间 |
| update_time | DATETIME | 非空 | 更新时间 |
| is_delete | TINYINT | 默认 0 | 逻辑删除 |

索引：`uk_user_account (user_account)`

### 2. space 空间表

空间模块（私有/团队空间）的核心表。公共图库不建 space 记录（对应 picture.space_id 为空）。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | 主键 | 空间 ID（雪花 ID） |
| space_name | VARCHAR(128) | 非空 | 空间名称 |
| space_type | TINYINT | 非空 | 空间类型：0 私有 / 1 团队 |
| user_id | BIGINT | 非空 | 创建者用户 ID |
| create_time | DATETIME | 非空 | 创建时间 |
| update_time | DATETIME | 非空 | 更新时间 |
| is_delete | TINYINT | 默认 0 | 逻辑删除 |

索引：`idx_space_user_id (user_id)`、`idx_space_type (space_type)`

### 3. space_user 空间成员表

「空间成员与权限」模块的核心表，承载用户与空间的多对多关系 + 成员角色（RBAC）。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | 主键 | 成员关系 ID（雪花 ID） |
| space_id | BIGINT | 非空 | 空间 ID |
| user_id | BIGINT | 非空 | 用户 ID |
| space_role | VARCHAR(64) | 非空 | 角色：viewer / editor / admin |
| create_time | DATETIME | 非空 | 加入时间 |
| update_time | DATETIME | 非空 | 更新时间 |

索引：`uk_space_user (space_id, user_id)`、`idx_space_user_user_id (user_id)`

### 4. picture 图片表（逻辑表）

图片模块的核心表。分表方案见「五、分库分表说明」，按 `space_id` 分表。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | 主键 | 图片 ID（雪花 ID，作为与向量表的关联键） |
| name | VARCHAR(128) | 非空 | 图片名称 |
| url | VARCHAR(1024) | 非空 | 原图 URL（COS） |
| thumbnail_url | VARCHAR(1024) | 可空 | 缩略图 URL（COS） |
| pic_size | BIGINT | 可空 | 图片大小（字节） |
| pic_width | INT | 可空 | 图片宽度 |
| pic_height | INT | 可空 | 图片高度 |
| pic_format | VARCHAR(32) | 可空 | 格式：jpeg / png / jpg / webp |
| pic_color | VARCHAR(32) | 可空 | 平均主色调（用于按颜色搜索） |
| category | VARCHAR(128) | 可空 | 图片分类（用于分类分析） |
| tags | VARCHAR(512) | 可空 | 图片标签（JSON 数组字符串，用于标签分析） |
| space_id | BIGINT | 可空 | 所属空间 ID（空 = 公共图库） |
| user_id | BIGINT | 非空 | 上传者 / 作者用户 ID |
| create_time | DATETIME | 非空 | 创建时间 |
| edit_time | DATETIME | 可空 | 最近编辑时间 |
| update_time | DATETIME | 非空 | 更新时间 |
| is_delete | TINYINT | 默认 0 | 逻辑删除 |

索引：`idx_picture_space_id (space_id)`、`idx_picture_user_id (user_id)`

## 三、PostgreSQL 表设计

### 1. picture_embedding 图片向量表

以图搜图的向量表，通过 `picture_id` 与 MySQL `picture.id` 关联（逻辑外键，无真实外键约束）。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| picture_id | BIGINT | 主键 | 对应 MySQL picture.id |
| space_id | BIGINT | 可空 | 冗余空间 ID，用于「空间内」过滤 |
| embedding | vector(512) | 非空 | 图片特征向量，维度与 CI 向量特征提取一致 |

索引：

- 主键 `picture_id`
- HNSW 向量索引：`CREATE INDEX ON picture_embedding USING hnsw (embedding vector_cosine_ops);`
- `idx_picture_embedding_space_id (space_id)`

启用语句：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

## 四、表关系（ER）

- `user` 1 ─ N `space`（一个用户可创建多个空间，space.user_id 外键）
- `space` N ─ N `user`，通过 `space_user` 关联（space_user.space_id + space_user.user_id + space_role）
- `space` 1 ─ N `picture`（一个空间有多张图片，picture.space_id 外键）
- `user` 1 ─ N `picture`（一个用户上传多张图片，picture.user_id 外键）
- `picture`（MySQL）1 ─ 1 `picture_embedding`（PostgreSQL），通过 `picture_id` 跨库关联（逻辑外键，无真实外键约束，跨库一致性靠应用层补偿 + 定时对账保证，详见《事务设计文档》）

## 五、分库分表说明

- 分片键：`space_id`
- 逻辑表：`picture`
- 路由规则：`space_id` 为空 → 公共图库落 `picture` 表；否则落 `picture_{space_id}` 表
- 动态建表：团队空间创建时 `CREATE TABLE picture_{space_id} LIKE picture`
- 启用方式：在 `application.yml` 配置分片规则，启用 `DynamicShardingManager` 的 `@Component`，团队空间创建时动态建表
